## شروع بیمار

صفحه مستقیماً سؤال اول را نشان می‌دهد؛ در ورود تازه، حساب ساختگی «شروع تازه» (`09000000001`) برای امتحان مسیر باز می‌شود. اگر قبلاً وارد شده باشید، نقش و ادامهٔ همان پرونده محفوظ است. شروع با درد یا شکایت حاد اجباری نیست.

هر بار یک سؤال کوتاه می‌بینید. پاسخ تک‌گزینه‌ای خودکار جلو می‌رود؛ شهر، عدد و چندانتخابی تأیید صریح دارند. می‌توانید برگردید یا ذخیره و بعداً ادامه دهید. قوانین کوتاه زیر سؤال اول و خلاصه‌اند؛ متن کامل پشت لینک است. تیک‌ها خودکار نیستند. پاسخ‌دادن به معنی ارسال برای پزشک نیست؛ ارسال نهایی نیاز به پذیرش صریح دارد.

در خلاصه، پاسخ‌ها و موارد نامعلوم را می‌بینید و پزشک نمونه را انتخاب می‌کنید. نداشتن مدرک مانع شروع نیست. خلاصه نمرهٔ سلامت یا تشخیص خودکار ارائه نمی‌کند.

## مسیر شش‌مرحله‌ای

| قدم | بیمار چه می‌بیند؟ | تیم چه می‌کند؟ |
| --- | --- | --- |
| شناخت اولیه | سؤال، سابقه و اطلاعات تکمیلی اختیاری | پزشک گزارش بیمار را مرور و مورد نامعلوم را روشن می‌کند. |
| آشنایی با پزشک | پزشک مشخص، زمان پیشنهادی و خلاصهٔ ملاقات | پزشک ملاقات درخواست می‌کند؛ کارشناس هماهنگ می‌کند و بیمار زمان را تأیید می‌کند. |
| برنامهٔ شخصی | قدم، دلیل، مسئول، موعد و امکان موافقت/رد/تعویق | پزشک برنامه را منتشر می‌کند؛ تصمیم بیمار و نسخه‌های قبلی محفوظ‌اند. |
| هماهنگی مراقبت | ارجاع/آزمایش، مرکز پیشنهادی، اجازهٔ اشتراک و مراحل پیشرفت | کارشناس ارسال، پذیرش یا رد مرکز، زمان، مراجعه و دریافت گزارش را با شاهد ثبت می‌کند. |
| توضیح نتیجه | اصل گزارش، وضعیت بررسی، توضیح پزشک و قدم بعد | بررسی همین نسخه، امضا، انتشار، تحویل و تأیید دیدن جدا هستند؛ اصلاح، بررسی تازه می‌خواهد. |
| همراهی در ادامه | پیام، موانع، سوابق و پزشک جانشین پذیرفته‌شده | کار باز تا نتیجه یا تحویل پذیرفته‌شده مسئول دارد؛ پایان عضویت آن را پاک نمی‌کند. |

در «پیگیری‌ها»، مراجعه/نتیجه، درخواست کمک برای زمان/هزینه/رفت‌وآمد، اطلاعات تکمیلی و تصمیم دربارهٔ برنامه قرار دارند. اجازهٔ اشتراک برای مرکز مشخصِ همان ارجاع است؛ تغییر مرکز نیاز به اجازهٔ تازه دارد.

## حساب‌ها و نمونه‌های آماده

سربرگ فقط یک ورودی «حساب‌ها» دارد: انتخاب نقش، کد ورود قابل کپی، اجازهٔ تماس، راهنما، سوابق و عضویت و خروج. پیامک و پرداخت واقعی فعال نیستند.

| حساب | شماره | وضعیت نمونه |
| --- | --- | --- |
| شروع تازه | `09000000001` | مسیر را خودتان از سؤال اول بسازید. |
| سارا راد | `09000000002` | برنامه و گزارش موجود برای ادامهٔ بررسی. |
| نرگس شریفی | `09000000003` | ۱۴ ماه سابقه؛ ارجاع و پیگیری کامل. |
| امیر نیک‌روش | `09000000004` | بیش از یک سال؛ گزارش اصلاح‌شده منتظر بررسی تازه. |
| مریم کیانی | `09000000005` | یک سال؛ نتیجه توضیح داده شده و پیگیری کامل. |
| رضا احمدی | `09000000006` | دو ماه؛ زمان ارجاع منتظر تأیید بیمار. |
| لیلا موسوی | `09000000007` | مشکل نمونهٔ آزمایش و پیگیری کارشناس. |
| حمید صادقی | `09000000008` | بررسی اطلاعات اولیه. |
| هانیه رضایی | `09000000009` | هماهنگی اولین ملاقات. |
| علی رستگار | `09000000010` | پیشنهاد جانشینی؛ مسئولیت هنوز با پزشک فعلی. |

پزشک اول `09000000011` و کارشناس اول `09000000012`؛ پزشک دوم `09000000014` و کارشناس دوم `09000000015`؛ مدیر نمونه `09000000013`. پرونده نام پزشک و مسئول پیگیری را نشان می‌دهد. همهٔ اشخاص، مراکز هماهنگی، زمان‌ها، امضاها و مدارک نمونه ساختگی‌اند. PDFهای آماده با نام همان بیمار و واترمارک «ساختگی» همراه بسته‌اند.

## یک سناریو را کامل بررسی کنید

۱. بیمار تازه را تکمیل و با اجازهٔ تماس برای پزشک ارسال کنید.
۲. در پزشک اول، پرونده را باز و بررسی را شروع کنید؛ تکمیل اطلاعات یا ملاقات بخواهید.
۳. در کارشناس اول، تماس و زمان را ثبت کنید؛ در بیمار زمان را تأیید کنید؛ کارشناس انجام ملاقات فرضی را ثبت کند.
۴. پزشک از «مراقبت و پیگیری ← ملاقات» یادداشت خصوصی و خلاصهٔ بیمار را ذخیره/امضا کند و از «اقدام بعدی» برنامه منتشر کند.
۵. در «ارجاع»، نوع آزمایش/متخصص/کلینیک، دلیل و موعد را بنویسید. کارشناس از «ارجاع‌ها و موانع» مرکز پیشنهادی را مشخص کند؛ بیمار اجازهٔ همان مرکز را بدهد.
۶. کارشناس ارسال و پاسخ واقعیِ فرضی مرکز، زمان و مراجعه را ثبت کند. بیمار باید زمان را تأیید کند. برای آزمایش، وضعیت نمونه جدا ثبت می‌شود.
۷. کارشناس اصل PDF ساختگی را با منبع و شناسه دریافت کند. تطبیق نامطمئن تا تأیید پزشک برای بیمار نمایش داده نمی‌شود.
۸. پزشک از «اطلاعات و مدارک»، بررسی همین فایل را پیش‌نویس/امضا و سپس جداگانه منتشر کند. شکست تحویل و دیدن بیمار، مسئولیت پیگیری را خودکار نمی‌بندند.
۹. گزارش اصلاح‌شده را به نسخهٔ قبلی پیوند دهید؛ اصل قبلی و بررسی آن باقی می‌مانند و نسخهٔ تازه در صف می‌آید.
۱۰. پیشنهاد جانشینی را در پزشک دیگر بپذیرید؛ کارهای باز پس از پذیرش منتقل می‌شوند. بازگشت هم پذیرش می‌خواهد.

اگر بیمار مانع داشته باشد، کارشناس راه‌حل پیشنهاد می‌دهد یا به پزشک برمی‌گرداند؛ بستن مانع با تأیید بیمار است. فیلترهای صف پزشک، پرونده‌های مرتبط با کار باز یا موعد گذشته را باز می‌کنند.

## سوابق و عضویت

از «حساب‌ها ← سوابق من و عضویت» می‌توانید پروندهٔ خودتان را به ZIP بگیرید: JSON، نسخهٔ چاپی و اصل مدارک. برای PDF، نسخهٔ چاپی را باز و «چاپ یا ذخیره به PDF» را بزنید. یادداشت خصوصی پزشک در خروجی بیمار نیست.

خرید نمونه دارای حالت موفق، ناموفق، انصراف، رسید و دورهٔ ۳۰روزه است. مبلغ ۱٬۲۰۰٬۰۰۰ تومان فقط برای نمایش فرایند است؛ قیمت نهایی خدمت تعیین نشده و هزینهٔ مرکز جداست. لغو، پرونده یا مراقبت باز را حذف نمی‌کند؛ پزشک برنامهٔ ادامهٔ مراقبت را بررسی می‌کند.

## دو حالت اجرا

سایت عمومی GitHub Pages، **نمونهٔ مرورگری** است. داده‌ها روی همان مرورگر می‌مانند. دو نفر روی دو دستگاه در آن یک پایگاه مشترک ندارند.

داخل بسته، **سرور مشترک نمایشی** هم وجود دارد. Node.js 24 یا جدیدتر لازم است:

```sh
node shared-demo-server/main.mjs
```

سپس `http://127.0.0.1:4210/next/` را باز کنید. در دو مرورگر یا پنجرهٔ ناشناس، نقش‌های متفاوت را روی یک پرونده امتحان کنید. سرور، نشست، اسناد، تراکنش، تکرار فرمان و سابقهٔ دسترسی را نگه می‌دارد. این سرور روی GitHub Pages مستقر نیست و ورود سریع آن همچنان نمایشی است. [اجرای مشترک، پشتیبان و معماری](architecture/NEXT-SYSTEM-v3.1-fa.md).

برای اجرای همان حالت مرورگری از ZIP، همهٔ فایل‌ها را استخراج و اجراگر ویندوز/مک را اجرا کنید یا `python3 serve-demo.py` بزنید. Python 3 لازم است و پنجرهٔ سرور باید باز بماند. بازکردن مستقیم HTML، راهنمای اجرا نشان می‌دهد و بی‌پایان بارگذاری نمی‌شود.

## حدود این نسخه

از دادهٔ پزشکی واقعی استفاده نکنید. هویت، امضا، پرداخت، تماس، ویدئو، مراکز هماهنگی و تحویل پیام نمایشی‌اند. راهنمای فوری، مستقل از مراحل عادی در دسترس است؛ بستن آن مسئولیت هشدار ثبت‌شده را پاک نمی‌کند. فهرست تاریخ‌دار Geoapify/OpenStreetMap و مسیریابی نشان، جست‌وجوی زنده یا تأیید نزدیک‌ترین/بازبودن مرکز نیستند.

پروتکل و تیم واقعی، ساعت پاسخ، قراردادها، قیمت، احراز هویت واقعی، میزبانی داخلی و انتخاب مشروط Medplum/FHIR هنوز آماده‌سازی عملیاتی جداگانه می‌خواهند. اسناد و تصاویر نسخهٔ ۲٫۴٫۷ به‌عنوان مرجع حفظ شده‌اند؛ وجودشان به معنی پیاده‌سازی معماری تولیدی نیست.

## ساخت و آزمون سورس

```sh
cd source/site
npm ci
npm run build:next
npm run build:next:server
npm run test:next
```

بررسی نوع‌ها: `node node_modules/typescript/bin/tsc --noEmit`؛ قواعد کد: `npm run lint`. تست‌ها مسیر بیمار/پزشک/کارشناس، اصلاح گزارش، پوشش، مانع، لغو، دسترسی، ظرفیت، پایداری و راه‌اندازی دوباره/بازیابی سرور مشترک را بررسی می‌کنند. نتایج دقیق همراه نسخه در `source/review-evidence/next` هستند.
