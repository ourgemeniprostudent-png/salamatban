# فلوچارت و DFD سامانه همیار سلامت

نسخه: ۱.۰ — منطبق با MVP فعلی  
دامنه: سفر عضو، بررسی بالینی، تصویر سلامت، نقشه مراقبت ۱۲ماهه، پیگیری و نوبت‌دهی  
نکته: همه داده‌های نمونه در دمو ساختگی‌اند. این سند منطق محصول و جریان داده را توصیف می‌کند، نه پروتکل تشخیص یا درمان.

## ۱) فلوچارت اصلی سفر عضو

```mermaid
flowchart TD
    A([ورود به همیار سلامت]) --> B[ثبت شماره موبایل]
    B --> C[تأیید کد یکبارمصرف]
    C --> D[نمایش رضایت‌نامه‌ها]
    D --> E{همه رضایت‌های الزامی تأیید شد؟}
    E -- خیر --> D1[عدم تشکیل پرونده] --> Z([پایان])
    E -- بله --> F[ثبت مشخصات هویتی و راه ارتباطی]
    F --> G[انتخاب هدف اصلی و وضعیت بیمه]
    G --> H[پاسخ به شرح حال و سوابق]
    H --> I[انتخاب داروها از فهرست و ثبت دوز]
    I --> J[ثبت حساسیت دارویی و نوع واکنش]
    J --> K[بررسی علائم هشدار]
    K --> L{علامت هشدار فعال است؟}
    L -- بله --> M[نمایش راهنمای اقدام فوری]
    M --> N[ایجاد وظیفه تماس فوری با اولویت urgent]
    N --> O[قرارگیری پرونده در صف بررسی فوری]
    L -- خیر --> P[مرور خلاصه پاسخ‌ها]
    O --> P
    P --> Q{عضو صحت اطلاعات را تأیید کرد؟}
    Q -- خیر --> H
    Q -- بله --> R[بارگذاری آزمایش یا مدرک پزشکی]
    R --> S[قرنطینه و کنترل کیفیت مدرک]
    S --> T{مدرک تأیید شد؟}
    T -- خیر --> R1[اعلام رد و درخواست مدرک جایگزین] --> R
    T -- بله --> U[انتخاب طرح مراقبت سالانه]
    U --> V[ایجاد سفارش و پرداخت آزمایشی/واقعی]
    V --> W{پرداخت تأیید شد؟}
    W -- خیر --> V1[نمایش خطا یا تلاش مجدد] --> V
    W -- بله --> X[فعال‌سازی اشتراک]
    X --> Y[ارسال پرونده برای بررسی بالینی]
    Y --> AA[بررسی پزشک: پاسخ‌ها، دارو، حساسیت و مدارک]
    AA --> AB{تصمیم پزشک}
    AB -- نیاز به اطلاعات بیشتر --> AC[ایجاد وظیفه تکمیل اطلاعات] --> R
    AB -- ارجاع فوری --> AD[ثبت تصمیم ارجاع و بستن حلقه تماس]
    AB -- تأیید --> AE[ساخت پیش‌نویس تصویر سلامت]
    AE --> AF[ثبت جمع‌بندی، داروها، توصیه‌ها و پیگیری]
    AF --> AG[تأیید و انتشار تصویر سلامت]
    AG --> AH[ساخت نقشه مراقبت ۱۲ماهه]
    AH --> AI[نمایش داشبورد، نتایج و اقدام بعدی]
    AI --> AJ[اجرای اقدام‌ها، یادآوری و نوبت‌دهی]
    AJ --> AK{اقدام تکمیل شد؟}
    AK -- خیر --> AL[پیگیری مربی سلامت و یادآوری] --> AJ
    AK -- بله --> AM[ثبت شواهد انجام و به‌روزرسانی وضعیت]
    AM --> AN{نقطه تصمیم بعدی رسیده است؟}
    AN -- خیر --> AJ
    AN -- بله --> AO[مرور نتایج جدید توسط پزشک]
    AO --> AP[نسخه جدید تصویر سلامت یا ادامه برنامه]
    AP --> AQ{ماه ۱۲ کامل شد؟}
    AQ -- خیر --> AJ
    AQ -- بله --> AR[مرور جامع سالانه و طراحی دوره بعد]
    AR --> AS([پایان دوره / تمدید عضویت])
```

## ۲) فلوچارت پنل پزشک و تیم بالینی

```mermaid
flowchart TD
    A([ورود کاربر بالینی مجاز]) --> B[مشاهده صف بررسی‌ها]
    B --> C[مرتب‌سازی بر اساس اولویت و زمان]
    C --> D[باز کردن پرونده عضو]
    D --> E[نمایش هویت حداقلی، شرح حال و پاسخ‌ها]
    E --> F[نمایش داروها، دوزها و حساسیت‌ها]
    F --> G[نمایش مدارک تأییدشده و نتایج]
    G --> H{اطلاعات برای تصمیم کافی است؟}
    H -- خیر --> I[ثبت نیاز به اطلاعات بیشتر]
    I --> J[ایجاد care task برای عضو/تیم]
    J --> K[بازگشت پرونده به حالت پیگیری]
    H -- بله --> L{نیاز به ارجاع فوری وجود دارد؟}
    L -- بله --> M[ثبت تصمیم ارجاع فوری]
    M --> N[ایجاد وظیفه تماس فوری و ثبت Audit]
    L -- خیر --> O[ثبت جمع‌بندی بالینی]
    O --> P[ثبت توصیه‌ها]
    P --> Q[ثبت برنامه دارویی بدون تغییر خودکار نسخه]
    Q --> R[ثبت برنامه پیگیری]
    R --> S[تأیید بررسی]
    S --> T[ایجاد نسخه Draft تصویر سلامت]
    T --> U[تعریف اقدام‌های ۱۲ماهه]
    U --> V{عنوان، دلیل، موعد، مسئول و معیار تکمیل معتبر است؟}
    V -- خیر --> U
    V -- بله --> W[انتشار نسخه غیرقابل‌ویرایش تصویر سلامت]
    W --> X[فعال‌سازی Roadmap و اقدام‌ها]
    X --> Y[نمایش به عضو و ثبت Audit]
    Y --> Z([پایان بررسی])
```

## ۳) DFD سطح صفر — نمودار زمینه

```mermaid
flowchart LR
    MEMBER[عضو / بیمار]
    CLINICIAN[پزشک و تیم بالینی]
    OPS[اپراتور مراقبت]
    PAY[درگاه پرداخت]
    PROVIDER[آزمایشگاه / مرکز درمانی]
    MSG[سرویس پیامک و اعلان]
    SYSTEM((سامانه همیار سلامت))

    MEMBER -->|هویت، رضایت، شرح حال، دارو، حساسیت، مدارک، پرداخت، وضعیت اقدام| SYSTEM
    SYSTEM -->|وضعیت پرونده، تصویر سلامت، نقشه ۱۲ماهه، یادآوری، نتیجه نوبت| MEMBER

    CLINICIAN -->|تصمیم بالینی، جمع‌بندی، توصیه، برنامه دارویی و پیگیری| SYSTEM
    SYSTEM -->|صف بررسی، پاسخ‌ها، مدارک تأییدشده، نتایج و سوابق نسخه‌ها| CLINICIAN

    OPS -->|تأیید مدرک، هماهنگی، پیگیری وظایف| SYSTEM
    SYSTEM -->|وظایف باز، پرونده‌های ناقص، خطاهای هماهنگی| OPS

    SYSTEM -->|شناسه سفارش و مبلغ| PAY
    PAY -->|نتیجه تأییدشده تراکنش و مرجع پرداخت| SYSTEM

    SYSTEM -->|درخواست نوبت و حداقل داده مجاز| PROVIDER
    PROVIDER -->|تأیید، زمان و شناسه خارجی نوبت| SYSTEM

    SYSTEM -->|متن اعلان، مقصد و نوع پیام| MSG
    MSG -->|وضعیت تحویل| SYSTEM
```

## ۶) وضعیت‌های اصلی رکوردها

| رکورد | چرخه وضعیت پیشنهادی/فعلی |
|---|---|
| عضو | `started → completed` |
| پاسخ پرسشنامه | `submitted → review_pending → reviewed` یا `urgent` |
| مدرک پزشکی | `quarantined → approved / rejected` |
| سفارش | `created → paid / failed / refunded`؛ در MVP: `paid_test` |
| اشتراک | `active → expired / cancelled`؛ در MVP: `active_test` |
| بررسی بالینی | `pending → completed` با decision مستقل |
| تصویر سلامت | `draft → published`؛ هر اصلاح، نسخه جدید |
| Roadmap | `active → completed / superseded`؛ هر انتشار، نسخه جدید |
| اقدام Roadmap | `pending → completed` با Action Update و evidence |
| نوبت | `requested → confirmed / manual_pending / failed / cancelled` |
| Care Task | `open → completed` |

## ۷) فرهنگ داده و محل نگهداری

| کد | مخزن | داده‌های کلیدی | مالک نوشتن | مصرف‌کنندگان |
|---|---|---|---|---|
| D1 | D1/SQLite | member، consent definition، user consent، journey profile | عضو و سرویس عضویت | همه فرایندهای مجاز |
| D2 | D1/SQLite | questionnaire definition، response، answer، redFlagCount | عضو/موتور ارزیابی | پزشک، تریاژ |
| D3 | D1/SQLite + R2 | metadata، checksum، objectKey، status و فایل اصلی | عضو؛ تصمیم وضعیت توسط اپراتور بالینی | پزشک، کنترل کیفیت |
| D4 | D1/SQLite | plan، order، payment attempt، subscription | سرویس تجارت/درگاه | کنترل دسترسی خدمت |
| D5 | D1/SQLite | clinical review، decision، notes، health picture version | پزشک مجاز | عضو و تیم مراقبت |
| D6 | D1/SQLite | roadmap، action، dueDate، ownerType، completionRule، evidence | پزشک و عضو | داشبورد و پیگیری |
| D7 | D1/SQLite | care task، provider، integration، appointment، reminder preference | سیستم، اپراتور و عضو | عملیات مراقبت |
| D8 | D1/SQLite | actorId، subjectId، action، resource، purpose، outcome، timestamp | همه فرایندهای حساس | ممیزی و امنیت |

## ۸) قواعد کنترلی ضروری

1. هیچ خروجی بالینی بدون `clinical review` تکمیل‌شده و `approvedBy` منتشر نمی‌شود.
2. فایل پزشکی ابتدا با وضعیت `quarantined` ذخیره می‌شود و فقط نسخه `approved` وارد تصمیم پزشک می‌شود.
3. رضایت‌ها نسخه‌دارند؛ نوع رضایت، نسخه متن، زمان اعطا و منبع ثبت می‌شود.
4. حساسیت دارویی و فهرست دارو همراه دوز، بخشی از ورودی اجباری بررسی پزشک است.
5. وجود red flag خروجی تشخیصی تولید نمی‌کند؛ مسیر فوری، وظیفه تماس و پیام اقدام اضطراری می‌سازد.
6. `idempotencyKey` مانع ایجاد پرداخت و اشتراک تکراری می‌شود.
7. تصویر سلامت و Roadmap پس از انتشار درجا ویرایش نمی‌شوند؛ اصلاحات با نسخه جدید ثبت می‌شوند.
8. هر خواندن/نوشتن حساس باید با نقش، هدف استفاده و رویداد ممیزی قابل ردیابی باشد.
9. ارسال به ارائه‌دهنده بیرونی فقط پس از رضایت هماهنگی و با حداقل داده لازم انجام می‌شود.
10. اطلاعات کارت، OTP و رمزهای اتصال در مخازن بالینی ذخیره نمی‌شوند.

## ۹) مرز MVP و نسخه عملیاتی

- در دموی فعلی، OTP، پرداخت، ارائه‌دهنده و پیامک در حالت آزمایشی/شبیه‌سازی‌شده‌اند.
- داده‌های اصلی ساختاریافته در D1 نگهداری می‌شوند و فایل‌های پزشکی برای R2 طراحی شده‌اند.
- پنل پزشک، تأیید مدرک، بررسی بالینی، تصویر سلامت نسخه‌دار و Roadmap در مدل داده MVP وجود دارند.
- برای نسخه عملیاتی باید اتصال واقعی OTP، پرداخت، پیامک، ذخیره‌سازی امن فایل، SLA تریاژ و کنترل دسترسی سازمانی فعال شود.
