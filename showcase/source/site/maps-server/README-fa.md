# اجرای مستقل جست‌وجوی مراکز روی VPS

این سرور فقط واسط جغرافیایی Geoapify است؛ برنامهٔ پزشکی، ورود، پرونده‌ها و پایگاه D1/R2 را منتقل نمی‌کند. نسخهٔ دارای فهرست ثابت شهرها برای اجرا به این سرور احتیاج ندارد. این مسیر برای فعال‌کردن جست‌وجوی زنده در آینده آماده شده؛ ساخت موفق یا تست محلی، استقرار عمومی نیست.

## نیازمندی

- Node.js **۲۴ یا جدیدتر**، دیسک ماندگار و دسترسی خروجی HTTPS به `api.geoapify.com`.
- برای دسترسی عمومی: دامنه، HTTPS و reverse proxy مثل Nginx؛ کلید سرویس فقط در محیط امن سرور.
- برای شروع یک واسط کم‌مصرف، VPS لینوکسی با ۱ vCPU و ۱GB RAM نقطهٔ آغاز پیشنهادی است؛ این عدد حداقل اندازهٔ تضمین‌شده یا نتیجهٔ آزمون بار نیست. حجم فایل SQLite فقط مربوط به شمارنده‌های سهمیه است؛ هیچ دیتابیس جهانی نقشه یا پروندهٔ پزشکی بارگذاری نمی‌شود.

از پوشهٔ `site/`:

```sh
npm ci
npm run maps:build
npm run maps:test
npm run maps:start
```

ساخت، فایل `dist-maps-server/server.mjs` را تولید می‌کند. پس از ساخت می‌توان همین فایل را همراه Node24 روی VPS اجرا کرد؛ وابستگی npm در زمان اجرا لازم نیست. کلید هنگام ساخت خوانده یا در خروجی جاسازی نمی‌شود. برای اجرای مداوم از یک مدیر فرایند مانند systemd استفاده کنید و فرایند را با کاربر محدود اجرا کنید.

## تنظیمات زمان اجرا

| متغیر | کاربرد |
|---|---|
| `GEOAPIFY_API_KEY` | کلید فقط روی سرور؛ بدون آن، مسیر جست‌وجو `503 GEOAPIFY_NOT_CONFIGURED` می‌دهد |
| `GEOAPIFY_RATE_LIMIT_SECRET` | کلید مستقل اختیاری برای HMAC شناسهٔ محدودسازی؛ پیش‌فرض کلید سرویس است |
| `MAPS_DB_PATH` | مسیر فایل SQLite ماندگار؛ پیش‌فرض `.maps-data/rate-limits.sqlite` نسبت به پوشهٔ اجرای فرایند |
| `MAPS_PUBLIC_ORIGIN` | origin واقعی مثل `https://maps.example.org`، بدون مسیر یا query؛ برای انتشار باید تنظیم شود |
| `GEOAPIFY_ALLOWED_ORIGINS` | originهای مجاز مرورگر با ویرگول؛ دامنهٔ GitHub Pages پروژه از قبل در handler مجاز است |
| `MAPS_HOST` / `MAPS_PORT` | پیش‌فرض `127.0.0.1` و `8789`؛ فرایند به‌صورت پیش‌فرض مستقیم روی اینترنت باز نمی‌شود |
| `MAPS_TRUST_PROXY` | فقط مقدار اختیاری `loopback`؛ صرفاً پشت reverse proxy محلی که هدر زیر را بازنویسی می‌کند |

Secretها را در مدیر Secret یا فایل محیطی با دسترسی `0600` بیرون از ریشهٔ وب نگه دارید؛ آن‌ها را در Git، ZIP، دستور build یا تنظیمات عمومی سایت نگذارید. برای نمونهٔ systemd، `EnvironmentFile=/etc/salamatban-maps.env` و یک `WorkingDirectory` ثابت تعیین کنید. فایل SQLite و فایل‌های WAL کنار آن باید روی دیسک ماندگار باشند؛ حذف آن‌ها سهمیه را بازنشانی می‌کند. این پوشه نباید در ZIP، وب‌سرور یا نسخهٔ عمومی قرار بگیرد.

نمونهٔ بخش proxy در server موجود Nginx که HTTPS آن از قبل تنظیم شده است:

```nginx
location = /api/maps/hospitals {
    proxy_pass http://127.0.0.1:8789;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For "";
    proxy_set_header CF-Connecting-IP "";
    proxy_read_timeout 20s;
}
```

فقط با همین اعتماد مشخص، `MAPS_TRUST_PROXY=loopback` را فعال کنید. سرور هدرهای `X-Forwarded-For` و `CF-Connecting-IP` ورودی را نمی‌پذیرد؛ در حالت عادی IP اتصال را استفاده می‌کند. در حالت proxy، `X-Real-IP` فقط از اتصال loopback پذیرفته می‌شود و Nginx باید آن را بازنویسی کند. اگر CDN یا proxy دیگری پیش از Nginx وجود دارد، تنظیم اعتماد و IP واقعی آن جداگانه لازم است؛ این نمونه آن معماری را پیکربندی نمی‌کند.

## کنترل اجرا و اتصال سایت

`GET /healthz` روی فرایند محلی، زنده‌بودن فرایند را نشان می‌دهد؛ صحت کلید، موجودی اعتبار یا دسترس‌پذیری Geoapify را تأیید نمی‌کند. برای بررسی اتصال واقعی، پس از تنظیم کلید و دامنه یک درخواست جغرافیایی غیرشخصی به `/api/maps/hospitals?cityId=ir-tehran` و سپس از origin سایت ارسال کنید. پاسخ درست، CORS و مصرف حساب باید جدا بررسی شوند.

سهمیه‌ها همان limiter مشترک‌اند: ۱۲ درخواست هر IP در دقیقه، ۱۲۰ درخواست کل در دقیقه و ۸۰۰ درخواست کل در روز. شمارنده‌ها در SQLite ماندگارند و با راه‌اندازی دوباره صفر نمی‌شوند. IP خام ذخیره نمی‌شود؛ فقط HMAC آن وارد جدول محدودسازی می‌شود. این اعداد، سقف درخواست برنامه‌اند؛ سقف حساب Geoapify و مصرف چند فراخوانی برای هر جست‌وجو باید جدا بررسی شوند.

پس از استقرار و بررسی واقعی، هنگام ساخت سایت فقط **URL عمومی** gateway را در `SALAMATBAN_MAPS_GATEWAY_URL` قرار دهید. مقدار باید HTTPS و با مسیر `/api/maps/hospitals` باشد. کلید Geoapify وارد build مرورگر نمی‌شود. GitHub Pages فقط بخش استاتیک را منتشر می‌کند و این سرور را اجرا نمی‌کند.

آزمون `maps:test` با پاسخ ساختگی، HTTP محلی و SQLite موقت انجام می‌شود؛ جداسازی کلید، CORS، جعل IP، ماندگاری سهمیه و رد body در GET را بررسی می‌کند. این آزمون گواه استقرار VPS، TLS، سرویس واقعی یا ظرفیت عملیاتی نیست.
