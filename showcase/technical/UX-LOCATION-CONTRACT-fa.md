# قرارداد آدرس درخواست نمایشی — نسخهٔ ۱٫۵

`POST /api/pilot/booking` ورودی‌های فعلی `title`، `preferred` و `consent` را حفظ می‌کند. ورودی اختیاری `homeVisit: true` فقط در حالت `demo` مجاز است و `location` زیر را لازم دارد:

```json
{"address":"نشانی ساختگی","unit":"۱","entrance":"ورودی نمونه","latitude":35.7,"longitude":51.4,"confirmed":true}
```

آدرس حداقل ۵ و حداکثر ۵۰۰ نویسه؛ واحد ۸۰ و توضیح ورود ۲۰۰ نویسه. هر دو مختصات باید عدد محدود در بازهٔ معتبر عرض/طول باشند یا هر دو خالی باشند. مختصات بدون تأیید پذیرفته نمی‌شوند. ورود دستی آدرس با مختصات null معتبر است. در درخواست عادی، دادهٔ location ذخیره نمی‌شود.

خطاها: `LOCATION_CONFIRMATION_REQUIRED`، `INVALID_LOCATION`، `LOCATION_DEMO_ONLY` با وضعیت ۴۲۲. کنترل رضایت تماس و داشتن برنامهٔ پزشک همچنان برقرار است. محدودیت درخواست روزانه عوض نشده است.

ذخیره: جدول `pilot_booking_locations` با کلید خارجی `task_id`، متن آدرس/واحد/ورودی، مختصات nullable و `confirmed_at`. مختصات در SQLite به شکل متن عددی ذخیره می‌شوند. نسخهٔ مرورگری مهاجرت افزایشی دارد؛ D1 از `npm run db:local` استفاده می‌کند. مهاجرت تازه باید قبل از استقرار سرور اعمال شود.

نمایش فقط در درخواست خود عضو و صف هماهنگ‌کننده. پزشک در خواندن پرونده به آدرس درخواست دسترسی ندارد. در پایان یا لغو، عرض و طول null می‌شوند؛ نشانی متنی به‌عنوان سابقهٔ نمایشی باقی می‌ماند. برای تولید، سیاست مدت نگهداری و حذف، مسئول داده و ارائه‌دهندهٔ نقشه باید جداگانه تصویب و پیاده‌سازی شود.

کاتالوگ شهر از آدرس مستقل است: `profile.cityId` و `profile.provinceId` اختیاری، داخلی و وابسته به تطبیق نام شهرند؛ شهر آزاد بدون شناسه قابل ذخیره است. طرح PostgreSQL برای ۱۰۰۰ کاربر سند معماری هدف است و این افزودهٔ نمایشی به معنای اجرای آن طرح نیست.
